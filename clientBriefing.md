## 1. Иерархия сущностей

| Уровень        | Что это                                                |
| -------------- | ------------------------------------------------------ |
| Group          | Сообщество с именем, картинкой, описанием, theme color |
| Channel / Room | Комната внутри группы (= chat channel)                 |
| DM             | Отдельно (если делаете) — не комната группы            |

Имена групп уникальны (дубликатов нет).  
Комната может быть пустой (без участников) — это ок.

## Права

User

- сидит в группах/каналах, куда назначен;
- Может запросить создание новой комнаты (не создавать сам).
- может удалить свой аккаунт (если не мешают правила admin);
- Чат только в одной комнате одновременно.
- в комнате: слать / edit / delete своих сообщений только пока в сессии.

Group admin

- меняет группу: name, image, description (и theme color группы);
- Cоздаёт комнату сам -> request к Admin -> self-approve; после self-approve комната появляется.
- может создать/запросить комнату без участников;
- kick из своей группы (блок повторного входа в эту группу);
- Не может снять с себя admin, пока в очереди к superAdmin есть pending запросы.
- Не может удалить аккаунт, пока группа жива и он ещё admin (нужно передать роль или удалить группу через superAdmin);
- может просить superAdmin удалить группу → сам становится обычным user, группа исчезает.

SuperAdmin

- одобряет admin requests;
- Ban -> пользователь не может войти ни в одну группу.
- не может удалить себя;
? уникальность имён групп — на его/серверной стороне при create/approve. -- важное в брифинге, но не факт, что будет вручную проверяться самим админом.
Комнаты «только для админов» / admin-only channel — нет, создать комнату только для админов нельзя.

## Сообщения — ядро ограничений (самое важное)

Persistence
- Нет полноценного хранения истории.
- На сервере для joiners хранится максимум последние 5 сообщений комнаты.
- После leave локальная история стирается; вне last-5 ничего нет + те из 5, которые написал сам пользователь нельзя изменить после rejoin.
- Это не соцсеть: нет unread badges / индикаторов непрочитанного.
- Quote предыдущего сообщения — нет.
? Edit/delete через context menu (ПКМ) — на ваше усмотрение (разрешено дизайном).

Session
- Edit/delete своих сообщений — только в текущей сессии в комнате.
- Ушёл и вернулся -> сессия сброшена: даже свои старые сообщения нельзя править/удалять (кроме косвенного эффекта при delete account).
- Join channel -> клиент получает до 5 последних сообщений с сервера; всё, что было раньше last-5, для тебя «не существовало»
- Один user = одна комната одновременно — на клиенте и/или сервере: при входе в другую — leave предыдущей.
- Delete message 
    -> Клиент убирает сообщение из своего локального массива 
    -> (потом) Шлёт на сервер WS broadcast delete messageId всем в комнате 
    -> остальные scrub то же сообщение id из своих локальных списков.
    -> если id в last-5 на сервере — убрать оттуда = станосится меньше 5 для новеньких.
- Пока ты в комнате, все сообщения сессии крутятся вверх в локальном массиве (не ограничены пятёркой для текущих участников).
    -> Last-5 — только буфер для новых joiners и серверный срез.
 
Для Phase 1 (UI + user/group/channel JSON): достаточно экранов и mock «ты в комнате / не в комнате», last-5 можно заглушить. Реальный WS — Phase 2, но в phase1.md endpoints/assumptions уже опиши.

## Что можно выкинуть из старого breakdown

- Broadcast-only канал, comments под постами.
- Вечная история, isRead, forward, «сообщения после leave».
- Group admin сам CRUD каналов без approve.
- Отдельная сложная модель «чат = group|channel|dm» без иерархии — лучше: Group → Channel, плюс отдельный DM.
